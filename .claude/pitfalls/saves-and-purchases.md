# Сейвы и покупки

## Обработчик покупки живёт внутри `UpdateAsync`

`Monetization:ProcessReciept` помечает чек через `PurchasesHistoryStore:UpdateAsync`, и обработчик выдачи вызывается **внутри трансформ-функции**, которая не йилдит вообще:

```
DataStore request was added to queue...
Transform function error Callbacks cannot yield
```

Первая строка похожа на производительность, вторая — причина: покупка не выдаётся. Можно звать методы владельцев разделов (`SoftCurrencyService:AddCurrency`) и `RequestSave`/`Save`. Нельзя писать в `DataStore` даже через хелпер. Товар считается выданным в момент правки кэша владельца; отказы без йилда — `false`, чек остаётся в очереди.

«Не йилдит ли обработчик» проверяй чтением исходника: слова `UpdateAsync` и `WaitForChild` встречаются и в комментариях.

## `ProcessReceipt` обязан вернуть решение

Обёртка без `return` отдаёт `nil`, Roblox читает его как `NotProcessedYet`: Robux списаны, товар не выдан, чек повторяется на каждом заходе. В каркасе возврат есть — не потеряй при правке.

## `Profile:Save()` не йилдит

Метод кончается `task.spawn(SaveProfileAsync, self)` — на этом держится законность записи из обработчика покупки. Проверять исходником, а не именем. На неактивной сессии он предупреждает и выходит (`Attempted saving an inactive profile`), поэтому гвард `profile:IsActive()` обязателен.

`StartSessionAsync` йилдит долго: `FIRST_LOAD_REPEAT` 5 с, `LOAD_REPEAT_PERIOD` 10 с, угон по `SESSION_STEAL` 40 с. Без `Cancel` ушедший игрок держит поток и ключ. Замер передачи между двумя окнами: второй ждал 6.3 с и вышел по `Cancel`; после `EndSession` забрал ключ за 2.0 с.

## `MessagingService` и `BindToClose` в Edit шумят

```
MessagingService can only be executed by game server
Script 'ServerStorage.ProfileStore', Line 1340 - function RobloxMessageSubscription
```

или `BindToClose can only be called on the server` (строка 2208) — в зависимости от момента `require`. Артефакт режима, не дефект; замер передачи сессии в Edit завышен.

## ProfileStore молча перезаписывает чужой формат

Всё, что не похоже на `{Data, MetaData, GlobalUpdates}`, уходит в `overwritten = true` («Silently override with empty profile»). Перевод живой игры без мигратора стирает сейвы. Проверять чтением ветки, не пробой на живом ключе: проба и есть перезапись.

## Чтение раздела в `LoadSave`

Уроки времён папок `PlayerData`, перенесённые на разделы:

- **`or` подменяет сохранённый `false` и `0` дефолтом** (`data.x or default`). Сверяй с `nil` и по типу; строка на месте числа роняла весь вход.
- **Смена дефолта не выдаёт ничего старым игрокам**: их сохранённое значение уважается. Новым дефолтом закрываются только новые профили; старым — кодом.
- **Раздел в каждом плейсе с общим `DataStore` обязан читаться одинаково**: плейс, не знающий раздела, не тронет его, но плейс со старой схемой раздела перезапишет его своей.

## Разделы

- **Сервис, который меняет раздел, обязан реализовать `GetSave`.** Без него раздел уезжает прочитанным на входе: в сессии всё работает (кэш обновился), после перезахода откат — кулдаун не начался, купленное пропало. Признак — варнинг о разделе без `GetSave` в консоли.
- **Покупка пишется сразу, с дебаунсом** (`RequestSave`, 6 с): игрок уходит телепортом, и следующий сервер читает почти сразу. Мягкий предел `DataStore` — около одной записи в 6 с на ключ; сверяй с актуальными лимитами в документации Roblox.
- **Синхронная точка записи для всех** (конец раунда) при полном сервере даёт пик `UpdateAsync`; короткий `AutoSavePeriod` размазывает записи.
- **Отладочный пустой сейв — отдельный стор** (`ProfileStore.Mock`), а не ветвление на записи: ветвление протекает в боевой путь.
- **Лок, а не инкременты**: поля «владение / выбор» абсолютны, инкременты гонку по ним не снимают.

## Донат и софт-валюта

- Маршрут доната — по `ProductId`, не по нулевой цене (бесплатный стартовый предмет тоже стоит 0).
- Ответный ремоут не нужен: результат виден через атрибуты игрока; «ничего не изменилось» — честный ответ на гонку или чит.
