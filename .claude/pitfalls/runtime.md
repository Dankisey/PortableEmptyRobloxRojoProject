# Движок и рантайм

## Каркас и старт

- **Бесконечный йилд в `require` убивает клиент.** `workspace:WaitForChild("Debris")` на уровне модуля вешал конструктор `ClientCore` — это и есть `Unitialized controllers`. Никаких `WaitForChild` без таймаута на уровне модуля; папки мира — `WorldQuery.GetWorldFolder(name)`. То же с ассетами: `Assets:WaitForChild("X")` вешает ядро, если папку унесли.
- **Порядок обработчиков одного события не задан.** Один сервис снимал флаг «загружен» на `PlayerRemoving`, другой по нему решал, писать ли сейв, — запись шла через раз. Флаг, который снимает чужой обработчик того же события, гвардом быть не может; проверяй состояние, живущее дольше события.
- **Подписки внутри обработчика ремоута накапливаются**: на третий заход один клик слал три запроса, а первый заход работал идеально. Подписки — один раз в `Initialize`, ремоут меняет только состояние и `Visible`.
- **Порядок доставки между разными `RemoteEvent` не гарантирован.** Поза и импульс разными ремоутами дали «летит стоя». Что обязано примениться в порядке — едет одним сигналом.
- **Серверная валидация обязана проверять то, что реально используется.** Сервер сверял, что модель-аргумент есть в реестре, а действие применял к объекту вызывающего: аргумент ни на что не влиял. Удаление из реестра — через один метод, иначе связанный GUI рассинхронизируется.
- **Одно событие завершения — по флагу состояния** (`_isRunning`), а не по совпадению значений результата.

## Персонаж и респавн

- **На респавне `Backpack` пересоздаётся уже с содержимым**, раньше `CharacterAdded`:
  ```
  3.451  Player.ChildRemoved: старый Backpack удалён
  3.451  Player.ChildAdded:   новый Backpack, детей = 1   <- тул уже внутри
  3.452  CharacterAdded
  ```
  `backpack.ChildAdded` не сработает — перебирай существующих детей. `HumanoidRootPart` в этот момент ещё нет, и гвард `CharacterUtils.GetAlive` молча проваливал экипировку: игрок оставался без тула до конца сессии. Для `EquipTool` жди живой `Humanoid`, потом проверь, что персонаж не сменился.
- **Пути восстановления не проверяют, жив ли персонаж**: снятие анкора, возврат камеры с якоря обязаны отработать и на мёртвом, иначе игрок остаётся заанкоренным, а камера — на удалённом якоре.
- **Респавн в рэгдолле — штатным путём подъёма** (тот же метод завершения нокдауна): иначе нет `RagdollEnded` и иммунитета, а блокировка тулов остаётся. Флаг блокировки сбрасывается на респавне безусловно.
- **Не ждать персонажа внутри сеттера скорости** (`CharacterAdded:Wait()` блокирует вызывающего); состояние движения сбрасывать на `CharacterAdded`.
- **`PlayerScripts.PlayerModule` может не существовать**: в Play там `RbxCharacterSounds` и бутстрап, штатное управление в CoreScripts. Заморозка — `HumanoidRootPart.Anchored`; `WalkSpeed = 0` перетирают другие писатели.
- **Физику персонажа мерь на клиенте**: сервер видит реплику. `SpawnLocation` даёт пол `Y = 1`, `Baseplate` — `Y = 0`.

## Сетевое владение объектами

- **Клиент может двигать заанкоренный реплицированный парт локально**: серверная позиция за 2 с сдвинулась на `0.00`, клиентская — на `24.86`. Правка не реплицируется, сервер её не перебивает, пока сам не пишет. Серверная позиция такой модели — фикция.
- **Объект, поставленный сервером, сервер и забирает.** После снятия анкора владение уходит ближайшему клиенту, и тот продолжает со своей скоростью (брошенный предмет вылетал со скоростью броска). Порядок: `Anchored = false` → `SetNetworkOwner(nil)` (если `CanSetNetworkOwnership()`) → обнулить скорость. Запрет `SetNetworkOwner(nil)` относится только к персонажу.
- **`AlignOrientation` с дефолтным торком крупную сборку не держит** (`MaxTorque = 10000`, `Responsiveness = 10`): наклон `68–84°`. `RigidityEnabled = true` — наклон `0–1°`.
- **`FallenPartsDestroyHeight` уничтожает парты, а не модель**: модель остаётся пустой, `Destroying` не стреляет. Слушай модель и `PrimaryPart`, подметай реестр по таймеру.

## Звук

- **`Sound` с пустым `SoundId` не заканчивается никогда**: `IsPlaying = true`, `Ended` не стреляет, клон живёт до страховочного `MaxLifetime`. На каждом наведении курсора в `workspace` копились клоны по 30 с. Исправлено: `SoundPlayer:PlaySound` молча пропускает шаблон с пустым `SoundId`.
- **Записи из Creator Store разной громкости**: при одном `Volume` развал камня был втрое тише удара и тонул за ним. Сравнивай средний `PlaybackLoudness` при проигрывании на клиенте — он меряет саму запись и **не учитывает `Volume`**: итог считай как «запись × Volume», `Volume` можно ставить больше 1.
- `TimeLength` до загрузки равен 0 — время жизни на него не опирается. Шаблоны предзагружаются, иначе первый клик звучит с опозданием.
- Позиционный SFX: сервер рассылает имя и `BasePart`, каждый клиент играет локальный клон.

## Прочее

- **`TeleportService` в Studio всегда падает** с `Request Context Failure` — норма.
- **`GetPlayerByUserId` в обработчике чата может вернуть `nil`**: автор вышел, а ошибка в обработчике `TextChatService` ломает доставку всем. Гвард обязателен.
- **Team Create не синхронизирует разные плейсы** одного юниверса: общий код зеркалится руками со сверкой `.Source`.
